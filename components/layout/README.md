# components/layout

Layout and navigation building blocks for the app shell:

- `Sidebar.tsx` — the staff sidebar (brand, compose CTA, main navigation, current user block). It receives its width and positioning through `className` so the same content is reused on desktop and inside the mobile drawer. All links use `next/link`: brand and “Feed” to `/`, “Niños” to `/kids`, “Avisos” to `/avisos`, “Mi cuenta” to `/mi-cuenta` and “Cerrar sesión” submits a server action that signs the user out (destination screens not implemented yet render Next's 404 until their specs land). The compose CTA is the client `components/feed/ComposeButton.tsx`, which opens the global “Nueva publicación” modal without changing the URL. The `activeItem` prop (`NavItemId`) marks the current section, and the optional `onNavigate` callback is forwarded to every `Link` and to the compose button so hosts can react to navigation (e.g. closing the mobile drawer). The bottom user block shows the `full_name` of the signed-in user from `public.users`, with the first letter as avatar.
- `MobileMenu.tsx` — client component with the mobile top bar (hamburger button) and the left-side drawer with overlay/backdrop. It renders the shared `Sidebar` inside the drawer and forwards `activeItem` to it, passing `onNavigate` so the drawer closes as soon as any of its links navigates.
- `CurrentUserNavigation.tsx` — async server wrappers around `Sidebar` and `MobileMenu` that read the signed-in profile through the DAL. Pages render them inside `<Suspense>` boundaries so the static shell stays prerenderable while the session-dependent user block streams at request time.
